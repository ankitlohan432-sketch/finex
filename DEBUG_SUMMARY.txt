ISSUE: After successful login, page redirects back to login within 1 second

ROOT CAUSES (4 Issues Found):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

❌ BUG #1: RACE CONDITION IN AUTHCONTEXT
   Location: frontend/src/context/AuthContext.jsx, lines 22-28
   Severity: ⚠️ HIGH
   
   PROBLEM:
   Token stored in localStorage but axios interceptor doesn't pick it up 
   immediately, so getMe() call is sent WITHOUT token header.
   
   FLOW:
   1. Store token: localStorage.setItem('token', token)  ← token saved
   2. Call: getMe()  ← axios reads from localStorage
   3. Issue: Race condition - interceptor might read empty localStorage
   4. getMe() sent without Bearer token
   5. Backend returns 401
   6. 401 interceptor redirects to /login
   
   FIX: Add 50ms delay after storing token before calling getMe()


❌ BUG #2: AGGRESSIVE 401 REDIRECT IN API INTERCEPTOR
   Location: frontend/src/services/api.js, lines 16-25
   Severity: ⚠️ HIGH
   
   PROBLEM:
   401 handler immediately redirects WITHOUT checking if this is a login flow
   
   CODE:
   if (err.response?.status === 401) {
     localStorage.removeItem('token')
     window.location.href = '/login'  ← IMMEDIATE REDIRECT!
   }
   
   SCENARIO:
   1. User clicks "Sign In"
   2. Login succeeds, token returned
   3. Token stored, getMe() called
   4. getMe() fails with 401 (due to Bug #1)
   5. 401 handler redirects BEFORE error can be handled
   6. User back at login page
   
   FIX: Don't redirect if this is an auth endpoint or getMe() call


❌ BUG #3: PUBLICROUTE RETURNS NULL DURING LOADING
   Location: frontend/src/App.jsx, lines 34-38
   Severity: ⚠️ MEDIUM
   
   PROBLEM:
   function PublicRoute({ children }) {
     const { user, loading } = useAuth()
     if (loading) return null  ← Returns nothing!
     return user ? <Navigate to="/dashboard" /> : children
   }
   
   ISSUE: Returns null instead of loading screen
   RESULT: Causes flashing and timing issues
   
   FIX: Return LoadingScreen component instead of null


❌ BUG #4: MISSING IS_ADMIN FIELD IN RESPONSE
   Location: frontend/src/App.jsx (line 31) expects is_admin
   Severity: ⚠️ MEDIUM
   
   PROBLEM:
   Frontend AdminRoute checks: user?.is_admin
   But if backend doesn't return is_admin field, user object is incomplete
   
   REQUIRED CHECKS:
   ✓ User model has is_admin field
   ✓ user_to_dict() includes "is_admin"
   ✓ Backend login response includes is_admin in user object
   
   FIX: Verify backend model and response format
